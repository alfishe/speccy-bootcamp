# Sprinter Video Frame — SVGA Timing, PC-Like Architecture, Fundamentally Different

The Peters Plus Sprinter (Спринтер, 1997) is the most architecturally divergent "ZX Spectrum clone" still considered part of the family. Built around a **20 MHz Z80**, **1 MB of RAM**, **SVGA output**, and an **IDE interface**, it's closer to a CP/M-era business computer than to a Sinclair Spectrum. Its video timing is **SVGA-derived**, not PAL-derived — it shares almost no timing DNA with the 48K.

> [!NOTE]
> This article covers the **video frame timing** of the Sprinter. For hardware architecture (CPU, RAM, I/O, ISA bus), see the planned [sprinter.md](../../02_hardware/newgen/README.md) in the New Generation section. For the broader New Gen platform landscape, see [clone_timing.md § Modern FPGA Implementations](../../02_hardware/clones/clone_timing.md).

```
┌──────────────────────────────────────────────────────────┐
│  Peters Plus Sprinter Frame Timing                       │
├──────────────────────────────────────────────────────────┤
│  CPU clock:               20.000000 MHz                  │
│  CPU core:                Z80 (no extensions)             │
│                                                          │
│  Frame rate:              70.00 Hz (SVGA 640×480)        │
│  Frame duration:          14.286 ms                      │
│                                                          │
│  Video standard:          SVGA (NOT PAL)                 │
│  Display resolution:      640×480 (text)                 │
│                          320×240 (ZX Spectrum mode)      │
│                                                          │
│  T-states per frame:      ~285,714 at 20 MHz             │
│  Scanlines:               ~525 (SVGA 480-line mode)      │
│                                                          │
│  INT source:              VGA vertical sync              │
│  INT frequency:           70 Hz                          │
│                                                          │
│  Contention:              None                           │
└──────────────────────────────────────────────────────────┘
```

The Sprinter's frame timing is so different from a classic Spectrum that **most 48K software does not run unmodified**. The CPU has ~4× more T-states per frame than a 48K, but the frame rate is ~40% higher (70 Hz vs 50 Hz), which breaks any code that uses the frame interrupt for tempo.

## Why the Sprinter Is Different

The Sprinter was designed in 1997 as a **modernised Spectrum for business use**, with full CP/M compatibility, hard disk support, and a standard PC-style expansion bus. The hardware decisions reflect that goal:

1. **20 MHz Z80** — not an accelerator mode; the *base* clock. Five times faster than original Spectrum.
2. **SVGA output** — to drive modern monitors and provide 80-column text mode.
3. **1 MB of RAM** in 16 KB pages, paged via the SpeccyBoot protocol.
4. **IDE hard disk + FAT filesystem** — no tape, no floppy-only assumptions.
5. **PC/AT keyboard + PS/2 mouse** — not the original Spectrum keyboard matrix.

These decisions make the Sprinter powerful but isolate it from the classic Spectrum ecosystem. Software needs to be **specifically adapted** to run on it.

## Video Modes

The Sprinter supports several video modes via a custom video controller (a discrete-logic ASIC):

| Mode | Resolution | Colours | Notes |
|---|---|---|---|
| **ZX Spectrum** | 256×192 | 8 + bright | Standard Spectrum mode, 70 Hz refresh |
| **Text 80×25** | 640×400 | Monochrome | CP/M-compatible |
| **Text 80×30** | 640×480 | Monochrome | Sprinter's native text mode |
| **Text 80×50** | 640×400 | 16 colours | Enhanced text with attributes |
| **Graphics 640×480** | 640×480 | Monochrome | CP/M graphics |

In ZX Spectrum mode, the screen layout matches the 48K (256×192 pixels + attributes + border), but the **frame timing is independent** — the visible area is rendered at 70 Hz within an SVGA frame.

```
48K spectrum timing:
  256×192 pixels @ 50.08 Hz, embedded in PAL frame

Sprinter ZX Spectrum mode:
  256×192 pixels @ 70.00 Hz, embedded in SVGA frame
  Scan-doubled to 320×240 visible (pixels doubled vertically)
  Border area is rendered (not cut off) — variable width
```

## INT Timing and ISR Implications

The Sprinter's INT is generated by the SVGA vertical-sync signal:

- **Frequency**: 70 Hz (not 50 Hz)
- **Position**: At the start of the visible frame (top of screen)
- **Duration**: One scanline worth (~31 µs at 20 MHz ≈ ~620 CPU T-states)

```
Sprinter ISR implications:
  
  Music tempo: any 50 Hz music player runs 40% FASTER on Sprinter
  Example: A PT3 module playing for 1 minute on 48K will play
           for ~43 seconds on Sprinter — every song is sped up.
  
  Frame-based animation: every animation runs 1.4× faster
  Input polling: keys are read 70 times/sec instead of 50
  
  Solution: re-time music player to track wall-clock time, not frame count
           (use a divider to call the 50 Hz player only every ~1.4 frames)
```

> [!WARNING]
> Software that uses the frame interrupt as a wall-clock (e.g., FRAMES counter at `#5C78`) **drifts significantly** on Sprinter. A "1-second delay" based on 50 frames will actually take 0.71 seconds. Always probe the actual frame rate at startup if you need timing accuracy.

## Detecting Sprinter at Runtime

```z80
; Detect Sprinter via the SpeccyBoot ROM signature
DetectSprinter:
    ; Check for Sprinter's SpeccyBoot BIOS signature in ROM
    LD   HL,#0000           ; Start of ROM
    LD   A,(HL)
    CP   #F3                ; Sprinter BIOS starts with DI (#F3)
    JR   NZ,notSprinter
    
    ; Additional check: read Sprinter's model ID register
    LD   BC,#xFD            ; SpeccyBoot ID port (specific port varies)
    IN   A,(C)
    CP   #SPRINTER_ID       ; Expected value
    JR   Z,isSprinter
    
notSprinter:
    ; Fall through to classic Spectrum code
    RET
    
isSprinter:
    ; Sprinter detected — switch to 70 Hz frame budget
    RET
```

Detection is non-trivial because the Sprinter boots into a CP/M-like SpeccyBoot environment rather than the standard Spectrum ROM. Most software that targets the Sprinter is built specifically for it rather than trying to detect it at runtime.

## Sprinter Software Compatibility

| Software type | Compatibility |
|---|---|
| Pure CPU code (algorithms, math, data processing) | **Excellent** — runs ~5× faster |
| Graphics rendering to a Spectrum framebuffer | **Good** — but must be re-timed for 70 Hz |
| AY music players | **Poor** — tempo is 40% faster; needs divider |
| Race-the-beam multicolor effects | **Broken** — completely different scanline timing |
| Tape loaders | **N/A** — Sprinter has no tape interface |
| TR-DOS software | **Good** — Sprinter emulates TR-DOS via disk image files |
| CP/M software | **Excellent** — Sprinter's primary design target |

The Sprinter is best understood as a **"ZX Spectrum-compatible CP/M machine"** rather than a Spectrum clone in the strict sense.
