# MB-02 / MB-02+ — Czech Disk, DMA, and Memory Expansion

## Overview

The **MB-02** (and its successor, the **MB-02+**) is a high-end ZX Spectrum expansion interface designed in the early 1990s by Slovak and Czech engineers associated with the **8BC (Eight Bit Company)** group based in Zlín, Czech Republic. It combines on a single board:

- A **WD2797 floppy disk controller** supporting up to four drives with DD and HD density
- A **Z80-DMA chip** for fast memory-to-disk and memory-to-memory transfers
- **128K to 512K of battery-backed SRAM** (memory expansion + non-volatile storage for the OS)
- A **real-time clock** chip (RTC-72421) for time and date
- A **boot EPROM** holding the BS-DOS bootloader
- An **optional IDE interface** (the "MB-02+IDE" variant)
- A **Kempston Mouse Turbo** interface (on later revisions)
- A **Centronics parallel printer** port
- An **NMI button** with a menu (developed by Hood, Czech community)

The MB-02 runs **BS-DOS**, a DOS-style operating system that supports 1.8 MB HD floppy disks (vs. the 178 KB DD limit of the Soviet Beta 128 / TR-DOS). It is widely regarded as **the most advanced mass-storage interface ever produced for the ZX Spectrum**, a title it still holds in the retro-computing community.

Approximately **90 MB-02+ units** were manufactured, sold primarily into Germany, Austria, Slovakia, the Czech Republic, the Netherlands, the United Kingdom, and Poland. The interface is rare today but its design influenced the modern **MB03+ Ultimate** (FPGA-based successor) and several community clones.

This article covers the MB-02 hardware, port map, BS-DOS, the DMA quirk, and how to use the interface. For other disk-interface options, see [03_io/storage/beta_disk_interface.md](../storage/beta_disk_interface.md) and [03_io/storage/opus_discovery_format.md](../storage/opus_discovery_format.md).

## Why the MB-02 Mattered

In the late 1980s and early 1990s, the ZX Spectrum disk-interface landscape was dominated by:

- **Sinclair ZX Interface 1 + Microdrives** (1983) — slow, unreliable proprietary tape-loop cartridges
- **Beta Disk Interface / TR-DOS** (1985) — Soviet/Eastern-bloc standard, 178 KB DD disks, WD1793 controller
- **Opus Discovery** (1985) — UK standard, 178 KB DD disks, WD1772 controller
- **DISCiPLE / +D** (1987) — UK standard, 178 KB DD disks, WD1772 controller

All of these shared two limitations: (1) **single-density or low-density floppies only** (typically 178 KB per disk side), and (2) **no DMA** — all disk I/O was PIO (programmed I/O) by the Z80 CPU, which limited throughput to ~30 KB/s and consumed 100% CPU during transfers.

The MB-02 broke both limits:

- **HD floppy support**: 1.8 MB per disk (10× the Beta 128's capacity), and at 50 KB/s sustained throughput
- **Z80-DMA**: true bus-mastered data transfer, freeing the CPU during disk operations and enabling use of the bus for video or sound simultaneously

For the small but active Czech and Slovak demoscene, the MB-02 was the closest the Spectrum came to having a "real" disk drive with the kind of throughput that the Amiga and Atari ST enjoyed.

### Key chips

| Chip | Function | Notes |
|------|----------|-------|
| **WD2797** | Floppy disk controller | Western Digital; supports FM/MFM, SS/DS, SD/DD/HD; supersedes the older WD1793 used in the Beta 128. The +D/Triangle format is similar but the WD2797 has built-in data separator and write precompensation. |
| **Z80-DMA (RFT U858D)** | Direct memory access controller | **Must be the RFT U858D clone** — the genuine Zilog Z8410 will not work with BS-DOS due to an init-order bug in BS-DOS that Zilog's stricter chip rejects. The RFT clone is more permissive. |
| **RTC-72421** | Real-time clock | Provides seconds, minutes, hours, day, month, year; battery-backed. |
| **8K boot EPROM** | Boot loader | M1-triggered paged ROM that loads BS-DOS from disk into SRAM on boot. |
| **128K–512K SRAM** | Workspace and RAM disk | The original MB-02 had 128K; the MB-02+ expanded this to 512K (using four 128K SRAM chips). Optional battery backup preserves contents across power cycles. |

### Connectors

The MB-02 provides:

- **ZX Spectrum edge connector** (input, from the host Spectrum)
- **Pass-through edge connector** (output, for further peripherals)
- **34-pin floppy connector** (standard PC floppy cable, supports 4 drives)
- **Centronics 36-pin parallel port** (for printer — see [printers.md](printers.md))
- **9-pin D-sub joystick port** (Kempston joystick, optional on later revisions)
- **9-pin D-sub mouse port** (Kempston Mouse Turbo, on later revisions)
- **IDE 40-pin header** (MB-02+IDE variant only — for CompactFlash or hard disk)
- **NMI button** (red, on the back panel)
- **Reset button** (on the back panel)

## I/O Port Map

The MB-02 uses the host Spectrum's standard port-decode scheme with addresses in the `#xxDF`/`#xxDD` range (selected by the high address bits) and additional registers for the DMA and RTC. The full port map (from the BS-DOS source code and 8BC documentation):

| Port | Direction | Function |
|------|-----------|----------|
| `#01DF` (write) | W | WD2797 command register |
| `#01DF` (read) | R | WD2797 status register |
| `#03DF` (write) | W | WD2797 track register |
| `#03DF` (read) | R | WD2797 track register |
| `#05DF` (write) | W | WD2797 sector register |
| `#05DF` (read) | R | WD2797 sector register |
| `#07DF` (write) | W | WD2797 data register |
| `#07DF` (read) | R | WD2797 data register |
| `#09DF` | W | FDC control flags (side select, density, motor-on) |
| `#0BDF` | R | FDC side / drive / density status |
| `#0DDF` | R/W | Z80-DMA registers (in WR0–WR6 sequence) |
| `#0FDF` | W | Memory paging register (select 16K SRAM bank at `#0000-#3FFF`) |
| `#1FDF` | R/W | RTC-72421 register select + data |
| `#0F` (Centronics) | W | Centronics printer data (same as Kempston/DK'Tronics convention) |
| `#1F` (Centronics) | R | Centronics printer status (BUSY bit 7) |
| `#1F` (Kempston joy) | R | Kempston joystick (only on revisions with joy port) |
| `#FBDF` (Kempston mouse) | R | Mouse X (only on revisions with mouse port) |
| `#FFDF` (Kempston mouse) | R | Mouse Y |
| `#FADF` (Kempston mouse) | R | Mouse buttons |

### Memory paging register (`#0FDF`)

Writing to `#0FDF` selects one of the 32 possible 16K SRAM banks (for the 512K expansion) and overlays it into the `#0000-#3FFF` window (where the host Spectrum's ROM normally lives). The host's `/ROMCS` line is pulled high during this overlay, exactly as the Interface 1 / Multiface shadow-ROM trick does — see [zx_bus.md](zx_bus.md) for the bus-level mechanism.

The paging register has these bits:

| Bit | Meaning |
|-----|---------|
| 7 | If 1, disable the overlay (return to host ROM) |
| 6 | If 1, write-protect the overlaid SRAM bank |
| 5-0 | Bank number (0-31 for 512K; 0-7 for 128K) |

When the overlay is enabled, the boot EPROM is also mapped to `#0000-#1FFF` and the selected SRAM bank to `#2000-#3FFF` — until BS-DOS relocates itself into pure SRAM and disables the EPROM.

### Compatibility jumper

The MB-02+ has a hardware jumper (`W1`) that selects between 48K Spectrum mode and 128K/+2/+2A/+3 mode. In 128K mode, the MB-02+ cooperates with the host's `#7FFD` paging register rather than fighting it; in 48K mode, the MB-02+ is the sole memory pager.

## BS-DOS

**BS-DOS** is the disk operating system that ships with the MB-02. It is a CP/M-like OS providing:

- A flat filesystem on floppy disks (HD = 1.8 MB, DD = 720 KB)
- File naming: 8.3 format (NAME.EXT)
- A `bsdos` RAM bank (~16K) that pages in over the host ROM on demand
- BASIC extensions: `LOAD "filename"`, `SAVE "filename"`, `CAT`, `ERASE`, `FORMAT`, etc. (same vocabulary as +3DOS / TR-DOS, different syntax for some commands)
- A `*` system-call interface (similar to BDOS function calls in CP/M) for assembly-language programs
- A resident NMI handler: pressing the NMI button brings up Hood's menu (file browser, screen save, snapshot, OS shell)

### BS-DOS boot sequence

1. Power-on. The 8K boot EPROM is mapped to `#0000-#1FFF`. The Z80 starts executing from `#0000`.
2. The EPROM initializes the WD2797, Z80-DMA, and RTC; verifies SRAM; and looks for a boot floppy in drive A:.
3. If found, the EPROM loads the BS-DOS image (one sector) from disk into SRAM bank 0.
4. The EPROM then transfers control to the BS-DOS entry point in SRAM.
5. BS-DOS initializes its workspace, hooks the BASIC ROM's `RST 08` (error handler) to dispatch BASIC extensions, and returns to the BASIC prompt.

The boot floppy must be present at every cold boot — the EPROM cannot initialize the system from IDE alone (see Ingo Truppel's note about the IDE upgrade). This is the same limitation as +3DOS, which also requires a boot floppy.

### HD floppy capacity

The WD2797 with the proper data separator supports both DD (250 Kbit/s MFM) and HD (500 Kbit/s MFM) density. The exact capacity depends on the BS-DOS `FORMAT` command:

- **DD disks**: 80 tracks × 2 sides × 10 sectors × 512 bytes = **819,200 bytes (800 KB)** formatted
- **HD disks**: 80 tracks × 2 sides × 18 sectors × 512 bytes = **1,474,560 bytes (1.4 MB)** formatted, or up to ~1.8 MB with 20-sector tracks and reduced inter-sector gaps

Ben Versteeg's MB-02 page advertises 1.8 MB capacity for HD floppies; this is the **unformatted** capacity (the theoretical maximum before filesystem overhead). Usable capacity after formatting is typically **1.2-1.4 MB** — still roughly 10× the Beta 128's 178 KB DD capacity.

### BS-DOS file format

BS-DOS files use a flat structure: the first sector of a file is a header (containing filename, size, attributes, and a flag indicating whether the file is a BASIC program, a code block, a screen, or a character array). The remaining sectors contain the file data. The structure is similar to TR-DOS but with larger files (no 128 KB limit) and longer filenames.

For archival purposes, BS-DOS disks are typically imaged to **.MBD** files — a raw sector-by-sector dump with a small header recording the disk geometry. See [03_io/storage/README.md](../storage/README.md) for the disk-image format reference.

## The DMA Quirk

The MB-02+ uses the Z80-DMA chip for all disk I/O. The chip is a complex beast with 7 write registers (WR0-WR6), each accepting a variable-length command sequence. The Zilog reference manual specifies a **specific order** in which these registers must be initialized; deviating from that order causes undefined behavior.

The BS-DOS authors did not follow Zilog's recommended order. On the genuine Zilog Z8410 chip, this means disk writes (and any other DMA-initiated operation) silently fail. On the **RFT U858D clone** (an East German second-source), the chip is more permissive and tolerates the out-of-order initialization — disk I/O works correctly.

This is a well-documented phenomenon. From Ingo Truppel's correspondence (quoted on Ben Versteeg's MB02 page):

> "You will not find a better one. If you replace it with the Zilog one or any other clone know that writing to disk will not work. The reason is that there is a bug in BS-DOS. Zilog recommends a special order of initializing statements for the DMA. The authors of BS-DOS did not care about this and therefore writing to disk (or any other IO-device) via DMA does not work. The RFT clone U858D has advanced properties and doesn't care about errors in the initializing order."

For MB-02+ repairs today, the RFT U858D is the required part. These chips were manufactured in East Germany until 1990 and are increasingly rare; substitutes from Russia (the KR580VT7) sometimes work but are not guaranteed.

## Compatibility

| Host Spectrum model | MB-02+ supported? | Notes |
|---------------------|-------------------|-------|
| 16K, 48K, 48K+ | ✅ | Full functionality; set jumper W1 to "48K" mode |
| 128K (heatsink) | ✅ | Set W1 to "128K"; clock-signal reliability is poor on this model — may need extra pull-up resistor on the CK line |
| +2 grey | ✅ | Best compatibility; clock signal is clean |
| +2A, +2B | ✅ | Set W1 to "128K"; the missing `/ROMCS` line is worked around by the MB-02+ hardware |
| +3, +3B | ✅ | Same as +2A; cooperative paging with the +3's `#1FFD` register |
| Pentagon, Scorpion | ⚠️ | Not directly compatible — Soviet clones have their own disk interfaces (Beta 128). The MB-02+ uses 2.54 mm pitch; Soviet clones use 2.5 mm. A passive adapter may work but isn't guaranteed. |
| ZX Spectrum Next | ❌ | The Next has its own expansion connector and FPGA-based MB-02+ emulation built in (in the MB03+ layer) |
| TS2068 | ❌ | Different expansion connector |

### Coexistence with other peripherals

The MB-02+ typically must be **first in the chain** (closest to the Spectrum) because it intercepts `/ROMCS` and the `M1` line for its boot EPROM. It exposes a pass-through connector for further peripherals, but:

- **Multiface**: may conflict with the MB-02+ for `/ROMCS` and the M1 trigger address. The Multiface 3 has known compatibility issues with the MB-02+ on +2A/+3 hosts.
- **Kempston joystick / Centronics adapters**: the MB-02+ already provides these ports on-board, so external adapters are unnecessary and may conflict.
- **Sound expansions** (TurboSound, General Sound, Covox): these are passive and stack behind the MB-02+ without conflict.
- **ZX Printer**: the MB-02+ has its own Centronics port; the ZX Printer can plug into the MB-02+ pass-through connector.

### Stability and the cable-length problem

Ingo Truppel's correspondence and Ben Versteeg's testing both emphasize that the **distance between the Spectrum and the MB-02+ is critical**:

> "One big problem of using a longer cable between speccy and MB-02+IDE is indeed the clock line, ESPECIALLY USING a 128K heatsink!"

The 128K heatsink Spectrum has notoriously poor CPU clock generation. Extending the edge connector with a ribbon cable longer than ~10 cm causes:
- DMA failures (especially during disk writes)
- Random SRAM corruption
- Boot failures

The recommended setup:
- **MB-02+ directly plugged onto the Spectrum edge connector** (no cable)
- A **short, heavy-gauge ground wire** between the MB-02+ ground and the Spectrum ground (in addition to the edge connector's ground pins) — this prevents ground-fault damage if the edge connector's ground contact fails. The combined current of the Spectrum + MB-02+ is ~1.4 A; the edge connector fingers are not rated for this if any single contact should fail.

## History

### Pre-MB-02 era (1990)

The story starts in 1990 with two Slovak developers:

- **Robert "MDV" Letko** — built the **AP-01**, a ZX Spectrum-compatible computer with built-in 8255, 8251, Z80-CTC, Z80-DMA, and a floppy drive. The name "MDV" became the "M" in "MB".
- **Slavomír "Busy" Lábsky** — built a similar interface using a WD2797, Z80-DMA, 64K battery-backed RAM, two 8255 chips (6 parallel ports), memory LED maps, and connectors for two disk drives. The name "Busy" became the "B" in "MB".

Their combined work, the **MB-01**, was a hand-built hobbyist interface.

### MB-02 (1996)

Around 1996, the MB-01 was substantially improved into the **MB-02**. Two Moravian Speccy fans associated with the **8bc group**:

- **Last Monster (LMN128)** — design and FPGA/PCB work
- **Blazko / systems** — hardware and software

The MB-02 added:
- An RTC chip (RTC-72421)
- Up to 512K SRAM (the original MB-01 had 64K)
- A boot EPROM
- Support for 4 disk drives (up from 2)

### MB-02+ (late 1990s)

The "+" variant refined the design, fixed bugs, and added the optional **IDE interface** (the MB-02+IDE) for CompactFlash and small IDE hard disks. About **90 units** were produced.

### MB03+ Ultimate (2019+)

The modern FPGA-based successor, also by LMN128, replaces the entire MB-02+ with a single Xilinx Spartan-7 chip emulating all the original hardware (WD2797, Z80-DMA, RTC) plus many additional features: 16 MB RAM, multiple sound chips (AY, SID, SAA1099, YM2203), graphics enhancements (Timex HiColor, ULA+, Gigascreen, Radastan), and SD-card / CompactFlash storage. The MB03+ is the natural successor for users who want the MB-02+ experience without the rare 1990s hardware.

See [02_hardware/newgen/README.md](../../02_hardware/newgen/README.md) for the modern hardware ecosystem.

## Hood's NMI Menu

The Czech developer **Hood** developed an alternative NMI menu for the MB-02+, replacing the bare-bones BS-DOS NMI handler. Hood's menu provides:

- A file browser with directory navigation
- TAP-file loading (so tape images can be loaded as if from a real tape)
- Screen save (`.scr` files)
- Snapshot save (`.z80` and `.sna`)
- An OS shell to BASIC
- Configuration editor (memory mode, default drive, etc.)

Hood's menu is the de-facto standard NMI menu for MB-02+ today and is bundled with all modern firmware updates. The latest version is available at `hood.speccy.cz`.

## Common Pitfalls

1. **The DMA chip must be the RFT U858D clone, not the Zilog original.** Replacing a failed DMA chip with a Zilog Z8410 will cause disk writes to silently fail. The KR580VT7 (Russian clone) sometimes works but is not guaranteed.

2. **Boot floppy required.** The MB-02+ cannot boot from IDE alone — the boot EPROM requires a floppy disk to load BS-DOS into SRAM. This is a deliberate design choice (the EPROM is only 8K, too small for a full OS).

3. **The 128K heatsink model has a poor clock signal.** Use a +2 grey or a 48K for the most reliable MB-02+ operation. If using a 128K heatsink, consider adding a 180-ohm pull-up resistor on the CK line.

4. **Long cables cause DMA failures.** Plug the MB-02+ directly onto the Spectrum edge connector with no extension cable. If you must use a cable, keep it under 10 cm and add a heavy ground wire between the two devices.

5. **The combined current is ~1.4 A.** If the edge connector's ground contact fails, the full 1.4 A flows through the remaining ground pins and may damage them. Always add a separate ground wire as insurance.

6. **The paging register at `#0FDF` can disable the boot EPROM.** If your code accidentally writes to `#0FDF` with bit 7 set, BS-DOS disappears and the machine hangs. Always check the current paging state before writing.

7. **The HD floppy format must match between systems.** A floppy formatted on the MB-02+ as HD may not read on a PC (different sector layout) and vice versa. Use the BS-DOS `FORMAT` command to ensure compatibility.

8. **The Centronics port at `#0F` conflicts with Kempston/Centronics adapters.** Don't stack an external Centronics adapter on the MB-02+ pass-through — it will fight the MB-02+'s on-board Centronics port.

9. **Coexistence with the Multiface is problematic.** The MB-02+ and the Multiface both intercept `/ROMCS` and `M1`. The Multiface 3 has known issues; the Multiface 128 may work on 48K/+2 hosts. Test before relying on it.

10. **PC keyboard adapters (PCKI) can corrupt SRAM.** The PCKI's electrical load on the bus has been observed to cause intermittent data corruption when used with the MB-02+. Ben Versteeg's testing found no reliable solution.

11. **The MB-02+ is not directly compatible with Soviet clones.** Different edge connector pitch (2.54 vs 2.5 mm) and different banking signals. An adapter is needed.

12. **The IDE variant requires a separate driver.** BS-DOS does not natively support IDE — the IDE driver must be loaded from floppy on every boot, or the EPROM must be upgraded to a version with built-in IDE support.

## When to Use an MB-02 (Today)

| Use case | Recommendation |
|----------|----------------|
| Using original Czech/Slovak software distributed on BS-DOS floppies | Real MB-02+ hardware with an HD floppy drive, or the MB03+ Ultimate (which emulates the MB-02+) |
| Running original MB-02+ software on modern hardware | ZX Spectrum Next with the MB-02+ layer enabled, or the MB03+ Ultimate |
| Building new disk-based software for the Spectrum | Target TR-DOS (Beta 128) for widest reach, or +3DOS / esxDOS for modern emulators. The MB-02+ is too rare to be a primary target |
| Backing up BS-DOS floppies | Use the `.MBD` format on a PC with a CatWeasel or KryoFlux controller — the HD format is not readable by a standard PC floppy controller |
| Repairing a failed MB-02+ | The RFT U858D DMA chip is the hardest part to source. Substitutes: KR580VT7 (Russian, sometimes works), or roll the dice on Zilog (won't work with original BS-DOS but works with community-patched versions) |

## Modern Analogies

- **The MB-02+ ≈ a 1990s "all-in-one" PC expansion card**. Like the SoundBlaster + I/O cards of the same era, the MB-02+ crammed disk, RAM, parallel port, and clock onto a single board — but the ZX Bus lacked the bandwidth to do it elegantly.
- **The RFT U858D DMA quirk ≈ CPU errata that only surface with specific code.** Modern CPUs have dozens of errata that the OS works around; the MB-02+ took the opposite path: ship a hardware quirk and require a specific chip revision.
- **The 1.8 MB HD floppy capacity ≈ the Iomega Zip 100 of the late 1990s.** Both offered roughly 10× the standard floppy capacity at a fraction of the cost of a hard disk.
- **The boot-EPROM-loads-OS-from-floppy pattern ≈ the IBM PC's BIOS loading DOS from a floppy.** Both have since been superseded by BIOS/UEFI loading the OS from solid-state storage (CompactFlash, SD card).
- **The cable-length sensitivity ≈ SCSI termination problems**. Both are signal-integrity issues that don't show up until you try to extend the cable.
- **The MB03+ Ultimate ≈ the modern "FPGA-in-a-keyboard" retro computers** (MIST, MiSTer, ZX-Uno, Spectrum Next) — all replace discrete 1980s chips with a single FPGA, achieving perfect compatibility plus modern enhancements.

2. **8BC (Eight Bit Company) — MB Documentation I/II** — `8bc.com/sinclair/`. The original manufacturer's documentation, including the schematic, parts list, and the 512K SRAM upgrade instructions.
3. **MB-02+ English Manual** (PDF) — `ci5.speccy.cz/files/mb02_english_manual.pdf`. Official user manual covering installation, BS-DOS commands, and programming.
4. **Sinclair Wiki — MB03+ Ultimate** — `sinclair.wiki.zxnet.co.uk/wiki/MB03%2B_Ultimate`. History of the MB-family interfaces, predecessor description, and successor (MB03+) details.
5. **Ingo Truppel (Truppel Online)** — Manufacturer of the modern MB-02+IDE variant on a smaller 4-layer PCB with 512K SRAM.
6. **Hood's MB-02+ NMI menu** — `hood.speccy.cz`. The de-facto standard NMI menu firmware, with regular updates.
7. **GitHub: z00m128/mb-02plus** — `github.com/z00m128/mb-02plus`. Source code for BS-DOS 3.08 and the MB-02+ BIOS, formatted for SjASMPlus.
8. **Velesoft — DataGear** — `velesoft.speccy.cz/data-gear.htm`. Documentation of the standalone Z80-DMA expansion (extracted from the MB-02+ design), with timing diagrams.
9. **World of Spectrum forums** — Multiple threads on MB-02+ usage, troubleshooting, and repair.
