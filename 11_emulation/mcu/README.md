# Emulation — MCU Chip Emulation

This directory covers replacing vintage silicon with modern microcontrollers: Z80 on MCU, ULA on MCU, FDC, PSG, keyboard, video adapters, SD interfaces, and design patterns. MCU-based chip emulation is a growing trend in retro-computing — modern MCUs (especially the RP2040 with its PIO blocks) can replace ageing Z80s, ULAs, AY chips, and floppy controllers at lower cost, lower power, and with additional features like in-circuit debugging and tracing.

For FPGA-based chip emulation, see the [fpga](../fpga/) directory. For software emulators running on PCs, see the [software](../software/) directory.

| 2 | [mcu_ula.md](mcu_ula.md) | **ULA on a Microcontroller** — replacing the Ferranti ULA (most failure-prone original Spectrum component, no replacements available since Ferranti sold to Plessey/scrapped tooling) with an MCU. Why replace (ULA failure symptoms — no video, garbage screen, no keyboard, no sound, random crashes; Chris Smith's reverse-engineering book enables modern recreation; RP2040 PIO optimal for cycle-precise video). **ULA functions**: video generation (video address counter walking through display RAM, pixel shift register, attribute application via colour encoder, composite PAL signal with HSYNC/VSYNC/blanking/colour burst, BORDER mixing); memory arbitration (ULA shares RAM with CPU, asserts WAIT_n during active display producing contended memory timing in `0x4000–0x7FFF`); I/O ports (`0xFE` write for beeper/MIC/EAR/BORDER colour, `0xFE` read for keyboard matrix row via `A[8:15]`, `0xFF` floating bus); INT generation at scanline 64 every 20 ms; clock generation (14 MHz master / 4 = 3.5 MHz CPU); beeper (1-bit DAC via port `0xFE` bit 4). **Video generation on RP2040 PIO**: pixel timing (7 MHz pixel clock, 448 pixels/scanline × 311 scanlines); PIO program for composite video (load pixel data, shift out 8 pixels/byte × 32 bytes/scanline, HSYNC 4 µs, VSYNC sequence per PAL); composite signal requirements (HSYNC, VSYNC with PAL equalisation pulses, 4.43 MHz colour burst for compat, blanking levels); VGA alternative (separate HSYNC/VSYNC, RGB via resistor DAC, simpler than PAL); HDMI via Pico DVI (bit-banged DVI through PIO). **Contention emulation** via state machine: given video position + CPU accessing contended + cycle in 4-T-state character, decide WAIT_n; pseudocode for contention logic; integration with cycle-stepped Z80 emulator. **Floating bus emulation**: track ULA's current video fetch byte, return on `0xFF` read during contention cycle, otherwise `0xFF`. **I/O port tables** (port `0xFE` write bits 0-2 BORDER, 3 EAR, 4 MIC/beeper; port `0xFE` read bits 0-4 keyboard, 6 EAR). **Complete ULA replacement**: video address counter with bit shuffling (C code example with Y7-Y0 → addr 13 12 7 6 5 10 9 8 4-0); INT generation via timer; clock generation; beeper; 128K/+2/+3 considerations (memory banking via `0x7FFD`, AY-3-8912, different contention scheme, different video timing); integration with Z80/RAM/ROM/AY/keyboard/SD on single RP2040. Existing projects (Pico Spectrum, Yazoo's, PicoVGA, Pico DVI, SpecHMI). **Comparison with FPGA ULA recreation** (Harlequin/Sizif-512): MCU advantages (easier development C/C++, lower cost £1 vs £3-10, faster iteration reflash vs resynthesis, integrated peripherals, larger community) vs FPGA advantages (native parallelism, lower jitter, authentic bus signals, established solutions). Trade-off summary table. FAQ (RP2040 PAL composite via resistor DAC, cycle-exact contention with cycle-stepped, floating bus implementation, ULA+Z80 on single RP2040, composite vs VGA/HDMI trade-off, video memory buffer necessity, contention accuracy requirements for 95% software vs demoscene, 128K banking-aware contention). Summary (5 requirements: PIO-driven video, contention state machine, floating bus, I/O ports, INT generation). References (Smith's book, RP2040 datasheet, Pico Spectrum/PicoVGA/Pico DVI projects, PAL spec, Sensible tests). Cross-references |
